# docs/specs

Store durable specifications that implementation and review can rely on.

## What belongs here
- Product specs
- Technical specs
- API and contract specs
- Migration notes

## Naming
- `YYYY-MM-DD-short-spec-name.md`
- `feature-name-spec.md`

## Minimal spec template
1. Context
2. Objective
3. Scope
4. Out of scope
5. Contracts
6. Risks
7. Verification
