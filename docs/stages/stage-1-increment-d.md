# Stage Definition: Stage 1 / Increment D

## Name
Версионность + Приказы + Ручное указание влияющих документов

## Goal
Пользователь может создавать новые версии документов с комментариями, загружать внутренние приказы и привязывать их к документам, а также вручную указывать связи между документами.

## Scope
### Backend
1. Document versioning improvements:
   - Добавить version_notes в DocumentVersion
   - POST /api/v1/documents/{id}/versions — создать новую версию (загрузить новый файл)
   - GET /api/v1/documents/{id}/diff?from=v1&to=v2 — сравнение версий (метаданные, список изменений)
   
2. Document links (ручное указание влияющих документов):
   - Новая модель DocumentLink (source_document_id, target_document_id, link_type, is_manual, created_by)
   - GET /api/v1/documents/{id}/links — список связанных документов
   - POST /api/v1/documents/{id}/links — создать связь
   - DELETE /api/v1/documents/links/{link_id} — удалить связь
   - link_type: references, amends, supersedes, related

3. Internal Orders (приказы):
   - Новая модель Order (holding_id, title, order_number, order_date, description, status, file_path, file_type)
   - Новая модель OrderDocumentLink (order_id, document_id, link_type, description)
   - POST /api/v1/orders/upload — загрузить приказ (Word/PDF)
   - GET /api/v1/orders — список приказов
   - GET /api/v1/orders/{id} — детали приказа
   - PUT /api/v1/orders/{id} — обновить метаданные
   - DELETE /api/v1/orders/{id} — архивировать
   - GET /api/v1/orders/{id}/documents — список связанных документов
   - POST /api/v1/orders/{id}/documents — привязать к документу
   - Parser для приказов: извлечение реквизитов (номер, дата) + определение "какой документ изменяет"
   - При создании приказа, если определён изменяемый документ — автоматически создать DocumentLink

4. Alembic migration

### Frontend
1. Страница «Версии документа» — вкладка в DocumentDetailPage (улучшить)
2. Модал «Создать новую версию» — загрузка файла + комментарий
3. Страница «Приказы» — /orders — таблица приказов
4. Страница «Приказ» — /orders/{id} — детали приказа + связанные документы
5. Загрузка приказа — /orders/upload — форма + файл
6. Компонент «Связанные документы» — добавление/удаление связей на странице документа
7. Обновить Header — добавить «Приказы»

## Out of scope
- Визуальный diff документов (текстовое сравнение) — Stage 2
- Полноценный документооборот приказов (подписание, согласование)
- Автоматическое создание версий при изменении связанного документа

## Acceptance criteria
1. Можно создать новую версию документа с комментарием
2. История версий отображается с комментариями
3. Можно добавить ручную связь между документами (тип: ссылается/изменяет/отменяет)
4. Связи отображаются на карточке документа
5. Можно загрузить приказ (Word/PDF)
6. Приказ отображается в реестре приказов
7. Приказ можно привязать к документу
8. При загрузке приказа парсится номер и дата
9. При загрузке приказа определяется изменяемый документ (по тексту)
10. Все тесты проходят

## Risks
- Парсинг приказов: нет единого формата оформления реквизитов
- Связи могут создавать циклические зависимости — нужна защита

## Dependencies
- Increment A: auth, holdings
- Increment B: документы, парсинг
- Increment C: генератор (нужен для учёта приказов)
